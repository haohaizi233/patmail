# 发文与邮件

文件查询和期限监控在选定类型后都进入 `Forms/mail/mail.aspx`。邮件页的读取请求相同，创建发文的 Call 不同。

---

## MailCustomer

文件查询发文。来源：`HAR/选择发文类型并确定`、`HAR/跳转到发文`。

```http
POST /AjaxServers/Notice.ashx
```

页面：`FileSearchMail.aspx`。

| 参数 | 说明 |
|---|---|
| Call | 固定 `MailCustomer` |
| _file_ids | 文件 GUID，分号分隔。本次是 2 个 ID |
| _file_names | 文件名，分号分隔，段数与 `_file_ids` 相同 |
| mailtype | 发文类型 GUID |
| mailstyle | `1` 同客户合并发文；`2` 单个来文发文（2026-11-11 HAR 已确认） |
| log_pagename | `FileSearchMail.aspx` |

`FileSearch.js` 的 `FileManager.MailCustomer` 只读取响应里的 `objid`。有值时打开 `Forms/mail/mail.aspx?objid=` 加上这个 GUID。没有 `objid` 时页面不做跳转，也不读 `ClientInfo`。响应 234 字节，原文未保存，这个写接口没有重新调用。

### 2026-11-11 单个来文补证

来源：用户提供的本机 HAR `D:/Users/Administrator/Desktop/download`（不提交原始 HAR，避免包含会话和业务数据）。以下 entry 均为 HAR `log.entries` 的零基索引。

- entry 45：`POST /AjaxServers/Notice.ashx`，表单字段 `Call=MailCustomer`、`mailstyle=2`、`mailtype=<发文类型GUID>`、`_file_ids=<文件GUID>`、`_file_names=<对应文件名>`、`log_pagename=FileSearchMail.aspx`。本次仅一个文件。
- HTTP 200，响应结构如下（GUID 已脱敏）：

```json
{"ClientInfo":{"IsLogin":true,"Status":true,"Result":false},"objid":"11111111-1111-4111-8111-111111111111"}
```

创建成功依据是顶层有效 `objid`；`ClientInfo.Result=false` 在这份成功创建响应中也会出现，不能据此判定失败。后续 entry 111 `GetMailInfo` 和 entry 119 `GetMailFile` 读取创建邮件及文件。未确认结果时仍不自动重试创建。

文件管理工作流按本地 `single_file` 逐文件规划，每封传一个文件，并在 UI、消息校验、执行器到请求构造全链路传递 `mailstyle=2`；合并模式仍传 `1`。本次 HAR 没有验证 `mailstyle=2` 一次传多个文件时的返回行为，工作流不依赖该行为。

entry 148 `SaveMailInfo` 返回 `ClientInfo.Status=true, Result=false`；entry 150 `SaveMailRalteCaseFile` 返回 `ClientInfo.Status=true, Result=true`。保存成功仍按 `Status` 判断，关联按 `Result` 判断并回读文件；不以同一个标志判断所有写接口。

同一脚本里还有 `MailCustomerNew`。它不提交 `mailtype`，成功同样只看 `objid`，然后打开发文草稿页，不打开单封邮件。这次抓包走的是 `MailCustomer`。

期限监控不调用这个 Call，而调用同 Handler 的 `LimitMailCustomer`，且不提交 `_file_names`。见 [09-期限监控.md](09-期限监控.md)。

## SaveMailInfo

保存邮件草稿。来源：`HAR/提交发文（要获取客户）`。期限监控这组 HAR 没有再次抓到它。

```http
POST /AjaxServers/Mail.ashx
```

```text

```

`finish_ctrl_proc` 是完成事项。2026-10-12 期限监控发文的保存值是本封 `GetMailCase` 行里的 `ctrl_proc_id`（这次是提醒申请PCT 的 `629cd76f-d7ed-4bf9-944b-a9b2b91b84a2`），不是发文类型 GUID，也不是整棵处理事项树。同一事项只出现一次。草稿里这个字段经常是空的。PCT 相关发文保存时按本封案件补上。文件管理发文不补，沿用草稿里的原值。

本次 `is_zip=0`，`mail_bcc` 为空。收件人、主题和正文未写入本文。

`mail.js` 的 `Mail.SaveMailInfo` 与上面的字段一致。请求里的压缩包重命名键是 `renamezip`，`GetMailInfo` 返回的对应键是 `rename_zip`。成功回调只看 `ClientInfo.Status`。为真时提示保存成功，并立刻调 `SaveMailRalteCaseFile`。为假时读 `ClientInfo.Message`。2026-09-30 的期限监控发文抓包里，这份响应是 `ClientInfo.Status=true`、`ClientInfo.Result=false`、`Message` 为空，没有 `objid`。页面不读取 `objid`。
