# PatMail

专利发文辅助。在已登录的 EASY 页面上查询案件和期限，按工作流表格创建发文，并把信交给发文映射配置的默认审核人审核。人工仍在原站完成审核；插件不结束流程，也不代点通过。

仓库里是方案、接口记录和 Chrome 插件。没有独立后端。安装、构建和发文操作见 [patmail-extension/README.md](patmail-extension/README.md)。使用范围见 [LICENSE](LICENSE)：公开可见不表示可以复制或拿去做成别的产品。

从 [GitHub Releases](https://github.com/haohaizi233/patmail/releases) 下载公开安装包并解压。已使用解压版的用户可在任务结束后，用新包的 `dist/` 替换原加载目录，再在 Chrome 扩展管理页重载 PatMail、刷新 EASY 并重开工作台。保留原目录、原扩展和同一 Chrome 用户配置，可继续访问原来的本地数据。首次安装时选择「加载已解压的扩展程序」并指向 `dist/`。

## 现在能做的事

工作台从浮窗「打开工作台」进入。左侧「综合查询」下有文件管理、期限监控、递交管理和费用查询；请款、海牙新申请和季华实验室文件导入从「工作流」进入。系统设置可从左下角或头像菜单打开。

首页问候按本机钟点切换。下面那句从 5000 条知识产权日常文案里抽，每次重新打开首页换一句。系统设置里可以换头像：20 张预存不能删，自己上传的可以再选、再删。发文并发数也在这里，范围是 1 到 4，默认 1。

查询模板页把文件管理和期限监控分开。两边的条件不能混用。期限模板可以保存回网站。

文件管理查出的文件可以「下载已选」打成一个 ZIP：文件名来自下载名称模板或附件原名，可选申请号去点；开启去重后同案件按最终下载名只保留上传时间最新的一份，ZIP 条目重名由打包层追加编号。判定规则、边界和算法图解见 [下载去重算法](patmail-extension/docs/mechanisms/下载去重算法.md)。

递交管理是左侧单独一页，按原站递交列表的口径查询。条件组 `Element` 提交，处理事项、当前流程阶段、签约单位这些下拉从原站实时读取。「是否需要纸质通知书」「历史审核记录」「办理类型」的下拉取值没有抓包样本，这三项先按文本提交。发文记录先把当前页签读完，再在本地匹配：发文看主题、客户和收件人，提案看名称、客户和文号，递交看文号、客户和案件。网站自己的搜索框不承担这次筛选。

发文任务是当前主路径：

1. 在工作流里准备 PCT 提醒或鹏城专案，选定发文类型。
2. 在发文任务传入 `.xlsx`。表格提供客户、处理事项、IPR、技术负责人和第一联系人。邮箱列不参与发信。
3. 期限监控只列出还没结束的事项。表格文号另外走案件查询，已经结束的事项也能对上。
4. 勾选还没提交审核的事项，点「提交到 EASY」。

同一客户、收件人和抄送都相同的事项合成一封。创建时把这些处理事项的内部编号用分号拼进一次 `LimitMailCustomer`，`mailstyle` 为 `1`。收件人按工作流规则从发文页联系人里对上邮箱后写入，再 `MailSubmit` 给发文映射配置的默认审核人。原站预填的来文通知 `chenjch02@pcl.ac.cn` 在每次写入前去掉。

收件人规则：

| 工作流 | 收件人 | 抄送 |
|---|---|---|
| PCT 提醒 | 表格里的 IPR | 发文页商务 |
| 鹏城专案 | 技术负责人（去掉括号里的拼音） | 表格里的 IPR，以及发文页商务 |
| 文件管理 | 发文页的案件联系人 | 默认发件人，以及发文页商务 |

文件管理不读表格。客户、查询条件、发文方式和发文映射都用已经保存的配置。PCT 提醒里还可以写下特例客户：这些客户的收件人改成第一发明人，抄送改成表格里的 IPR。这不是单独的一条工作流。「递交管理-已完成导出」也不是发文工作流：在递交管理勾选递交记录后导出带退回脉络的 Excel，不创建发文、不提交审核。

进度在「提交到 EASY」弹窗里。每一行左边是时间，进度条右边是百分比。底部实时显示成功、失败、异常的件数；中途停掉时另计跳过。跑完后日志最后一行写出同样的统计。查询条件下面不再逐封粘贴「已提交」。

表格里的收件人或抄送对不上邮箱时，这一封不提交。回传后这些事项的审核状态标为「异常」，底色是浅橙。换表或换工作流会清掉这个标记。对不上包括：联系人里没有这个邮箱、对上多个邮箱、发文页没有商务邮箱、发明人没有可用邮箱。

写开关在系统设置，没存过时默认打开。扩展还没读完存储之前视为关闭。关掉后不会创建发文，也不会提交。

并发数大于 1 时，多封信可以同时提交。同一封里面仍是先创建，再写收件人，再提交。选 1 时，上一封有结果再发下一封。有一封结果没确认时，还没开始的不再开始；已经开始的会做完。

## 接口

EASY 使用 ASP.NET WebForms，接口入口是 `/AjaxServers/*.ashx`，动作由 `Call` 分发。插件按实际登录的 EASY 标签页发送请求，支持 Manifest 登记的 EASY 地址。鹏城客户资料在 `https://ip.pcl.ac.cn:81`。

和发文直接相关的调用：

| 动作 | 成功看什么 |
|---|---|
| `LimitMailCustomer` | `ClientInfo.Status=true`，并且有 `objid`。`Result=false` 仍可能已创建。`NeedConfirmFillAgency=true` 时停，不代为确认 |
| `SaveMailInfo` | `ClientInfo.Status=true` |
| `MailSubmit` | `ClientInfo.Result=true` 且 `Status` 不为 false。`finishdate` 为 false |
| `GetCaseBusFlow` / `ICSearchList` | 只读。用来判断事项停在哪，以及回传审核状态 |

`EndEmailFlowd` 不调用。下一节点若是结束、并行审核或需要全部审核，这一封不提交。创建或提交的响应无法确认时，不自动再创建、不自动再提交。

细节和尚未调用的接口见 [API/README.md](API/README.md)。

## 当前限制

- 审核状态的案件查询回传一次最多 40 件。超过的文号不会出现在这次回传请求里。
- 同一组合并后若对上了多种发文类型，整批勾选都不创建。
- 特例客户的计划抄送是 IPR。写入前仍要求商务邮箱出现在抄送里，因此这类信目前会停住，并让后面的信不再继续。
- 一封信的创建、写地址和提交走 30 秒通道。超时后页面会先收到失败，原站上的请求仍可能做完。提交账本在当前标签页，只留最近 500 个事项。
- 客户管理里另存的发文方式（一案一封、按第一联系人）不会改变发文任务这次的合并。发文任务固定按同客户、同收件人抄送合成一封。
- `patmail-extension/docs/` 里的阶段记录，以及 `API/` 里的接口原文，写的是当时核对到的事实。插件现在怎么工作，以本文件和 [patmail-extension/README.md](patmail-extension/README.md) 为准。
