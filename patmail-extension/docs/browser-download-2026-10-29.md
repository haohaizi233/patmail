# 纯浏览器下载（v1.6.0）

完整的dist目录可独立交付。使用者只需Chrome或Edge与原站EASY账号，不需Python、Node、EXE、启动脚本或本机HTTP服务。仓库start.py仍是开发构建入口，已不再启动下载桥接。

## 使用

1. 在扩展管理页加载或重新加载dist，刷新EASY与工作台。
2. 查询并勾选文件，点击“下载已选”，在浏览器保存弹窗选择目标ZIP。
3. 插件保留六个共享网络令牌，命名、读取附件和生成ZIP并行；彩虹条只展示名称生成。
4. 需要中断时点击插件“暂停下载”。继续时确认同一账号，恢复工作面后先刷新验证，再点“继续下载”并重新确认保存位置。

文件直接写入用户选定的位置，不建立Chrome右上角的原生下载记录；暂停和继续使用插件按钮。浏览器文件写入使用暂存提交机制，close成功才报告完成；暂停时可能留下未完成的ZIP，不能当作完整包使用。离开工作台、来源页或关闭浏览器都会停止当前生产，已确认缓存仍保留。

## 缓存与恢复

附件与ZIP片段存放在扩展自己的IndexedDB磁盘缓存，单块不超过256KiB，以SHA256校验。元数据、水位和二进制块在严格持久事务完成后才确认；大清单与片段元数据分开存储，避免每块重写整个任务。

完整附件从本地缓存回放，未完成附件依据ETag/Last-Modified和Range补取；原站不支持Range时仅重取该未完成附件。ZIP按冻结时间、名称和顺序重建，所有已确认前缀逐字节验证。重放会重写目标文件的已有前缀，不会因此重下完整附件。封存缓存可直接恢复写入目标文件。

完成需要ZIP封存、目标文件close成功两者确认，之后才保存完成回执、清理大块缓存。暂停/完成回执保留七天，按访问惰性回收。磁盘满、事务中止、权限丢失或片段校验失败明确暂停，不报告成功。扩展的unlimitedStorage权限用于大批量缓存，磁盘空间仍是实际限制；移除扩展、清除扩展数据或换成不同扩展ID会失去原缓存。

后台会验证来源标签和账号，目标句柄只留在选过文件的工作台。目标ID持久记录用于后台重启后的接管：旧writer确认关闭后才能打开新writer；明确已关闭的页面可安全接管，真实关闭失败则保留任务待重试。同页再次选择同任务也先关闭旧writer，支持时采用exclusive模式防止同时写入。

旧版Python缓存不会自动迁移到浏览器。旧任务可保留旧版完成，或在新工作台丢弃记录后重新下载；丢弃旧记录不会要求启动Python，也不会删除旧目录中的外部缓存。

## 验证入口

- `npm test`：账本、目标写入、来源隔离、接管、取消和缓存协议。
- `npm run test:e2e:browser-store`：真实IndexedDB严格事务、abort、损坏、并发、水位与TTL。
- `npm run test:e2e:browser-download`：真实扩展六路正文、断网、浏览器冷启动、续传、直接文件写入及ZIP CRC。
- `npm run test:e2e:download-editor`：查询一次后更改名称并重复保存、空标签及冷恢复。

浏览器夹具使用真实OPFS文件句柄代替操作系统保存弹窗，实际write/close由Chrome实现；同时检查选择器在点击手势有效时唤起。业务请求全部使用隔离响应，不调用真实EASY。

浏览器保存与权限依据：[File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。
