# 纯浏览器原生流下载（v1.6.1）

完整的dist目录可独立交付。使用者只需Chrome或Edge与原站EASY账号，不需Python、Node、EXE、启动脚本或本机HTTP服务。仓库start.py仍是开发构建入口，已不再启动下载桥接。

## 使用

1. 在扩展管理页加载或重新加载dist，刷新EASY与工作台。
2. 查询并勾选文件，点击“下载已选”，ZIP进入浏览器右上角原生下载记录，边生成边接收。
3. 插件保留六个共享网络令牌，命名、读取附件和生成ZIP并行；顶部彩虹条显示文件下载进度与命名、接收容量，入包完成后等待浏览器确认保存才到100%。导出按钮位于查询结果区域。
4. 需要中断时点击插件“暂停下载”。继续时确认同一账号，恢复工作面后先刷新验证，再点“继续下载”。

默认由浏览器管理保存位置，遵循浏览器下载设置。工作台以隐藏iframe导航到带一次性随机凭据的同扩展URL，MV3 fetch返回attachment流。直接调用downloads.download该URL不会经过此fetch，因此不用于此路径。无需HTTP服务，也不等待完整ZIP再建立原生下载记录。总长度未知时显示已收到字节，不伪造百分比。

暂停和继续使用插件按钮。在浏览器中暂停或取消也会使插件保留任务并停止生产；恢复时新建原生记录、从本地重放ZIP，附件完整缓存不向原站重下。离开工作台、来源页或关闭浏览器都会停止当前生产，已确认缓存仍保留。

## 缓存与恢复

附件与ZIP片段存放在扩展自己的IndexedDB磁盘缓存，单块不超过256KiB，以SHA256校验。元数据、水位和二进制块在严格持久事务完成后才确认；大清单与片段元数据分开存储，避免每块重写整个任务。

完整附件从本地缓存回放，未完成附件依据ETag/Last-Modified和Range补取；原站不支持Range时仅重取该未完成附件。ZIP按冻结时间、名称和顺序重建，所有已确认前缀逐字节验证。重放会重写目标文件的已有前缀，不会因此重下完整附件。封存缓存可直接恢复写入目标文件。

完成需要ZIP封存与Chrome原生记录complete两者确认，之后才保存完成回执、清理大块缓存。暂停/完成回执保留七天，按访问惰性回收。磁盘满、事务中止、权限丢失或片段校验失败明确暂停，不报告成功。扩展的unlimitedStorage权限用于大批量缓存，磁盘空间仍是实际限制；移除扩展、清除扩展数据或换成不同扩展ID会失去原缓存。

后台验证来源标签、账号、任务和目标。一次性导航凭据只发给已注册的工作台，页面拒绝其他来源导航指令。旧流取消后才能接管。原生消费背压只约束ZIP输出，不占用缓存/状态/暂停的后台队列。持久模式已完成的附件只保留轻量描述符，不再受48文件前瞻屏障阻塞；网络总并发仍不超过六路。单附件取句柄的502/503/504有限重试三次；发文和其他业务写入不受此改动影响。

旧版Python缓存不会自动迁移到浏览器。旧任务可保留旧版完成，或在新工作台丢弃记录后重新下载；丢弃旧记录不会要求启动Python，也不会删除旧目录中的外部缓存。

## 验证入口

- `npm test`：账本、目标写入、来源隔离、接管、取消和缓存协议。
- `npm run test:e2e:browser-store`：真实IndexedDB严格事务、abort、损坏、并发、水位与TTL。
- `npm run test:e2e:browser-download`：真实扩展六路正文、502、断网、浏览器冷启动、续传、原生字节增长及ZIP CRC。
- `npm run test:e2e:download-editor`：查询一次后更改名称并重复保存、空标签及冷恢复。

浏览器夹具直接观察真实Chrome下载记录，并saveAs读取实体ZIP验证CRC；选择器若被调用则测试失败。业务请求全部使用隔离响应，不调用真实EASY。

独立长流测试：`node tests/e2e/native-stream-lifetime.e2e.mjs`，跨越五分钟验证同一原生流。历史直接文件写入模块保留独立单测，新界面默认不再使用选择器。
