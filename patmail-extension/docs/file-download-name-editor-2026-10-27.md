# 动态下载名称模板修复（v1.4.4）

## 原站行为与根因

原站 `FileSearch.js` 的 `FileManager.selectTemp` 遍历选中模板的完整配方。例如：

```text
new_filename = app_no;-;case_name;-;file_desc
file_name_type = colname;txt;colname;txt;colname
```

对应“申请号 + 固定字符 - + 案件名称 + 固定字符 - + 文件描述”五段。原站按段创建 `selfilenameN`，固定字符另显示 `txtfilenameN`。

插件已经读取模板配方元数据，下载也能使用模板，但界面写死一个 `selfilename1`，选择模板仅改变模板ID，没有动态回显各段。因此后台有完整内容，前端仍是单一下拉。

## 修复

- 选模板后按顺序展开全部名称段，固定字符回显文本；可增加、删除和修改，最多31段。
- 读取本次完整编辑结果用于下载和客户绑定。编辑后去掉模板ID，避免下载时原站模板重新加载覆盖本次修改；未编辑仍使用账号模板。
- 元数据异步到达时补齐显示；同模板字典刷新保留手工编辑。用户明确重选同一模板、空项、恢复模板或重置账号，则还原对应内容。
- 空固定字符、分号及超长等无效配方显示原因，并阻止下载和客户绑定。无效原因跨组件传递，不能以 `null` 静默删除客户原有命名配置。
- 配方仅用于文件名，不加入查询条件。不新增原站模板写入操作，现有“保存下载名称”按钮仍会提示前往原站保存；本次编辑不自动写入原站账号模板。

## 验证入口

- `tests/unit/ui/download-name-editor.test.ts`：真实查询组件选模板、五段回显、固定文本、清空、恢复、同值重选、编辑后的实际GetFileName参数、无效文本阻止下载。
- `tests/unit/ui/bind-download-name-validation.test.ts`：无效配方禁用客户绑定，直接派发点击事件也不能保存或删除已有配方。
- `tests/e2e/download-editor.e2e.mjs`：加载构建后的插件，从界面选模板、修改、查询、勾选、点击下载，经后台与内容脚本后核验GetFileName收到的完整配方。所有网络被夹具拦截，在打包阶段主动返回夹具错误，不下载业务文件。
- `scripts/download/audits/live-download-name-editor-audit.mjs`：显式只读登录，在隔离浏览器读取真实账号模板，验证五段、两个固定字符框、增删与清空恢复，并保存界面截图。不查询、下载业务文件，不保存原站模板。凭据只从进程环境读取，不写报告。

测试和构建产物保存在忽略入库的 `test-results/download-editor-*`；真实模板界面为 `test-results/download-editor-live.png`。

## 本次验收结果

- 完整测试132个文件、844个用例通过，类型检查及两段生产构建通过。
- 构建后浏览器回归通过：五段回显、无效固定字符不请求命名、修改后的完整配方进入GetFileName、同一模板重选恢复原固定字符。
- 隔离浏览器读取真实账号模板，显示“申请号、固定字符、案件名称、固定字符、文件描述”，固定文本分别为“-”和“-”；增删、清空和重选通过。未查询、下载业务文件，未写账号模板。
- 独立复核指出的“无效配方误清空客户命名”和“同值重选不恢复”均补充先失败后通过的回归并修复，复核未发现剩余重要问题。
