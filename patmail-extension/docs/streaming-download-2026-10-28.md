# 流水单ZIP下载与浏览器原生进度（v1.5.0）

v1.5.1 已将持久缓存的网络窗口与ZIP消费分开，旧的6文件消费窗口说明不再适用于持久模式；当前限制和性能证据见 [下载空转排查](download-idle-audit-2026-10-28.md)。

v1.5.0 已加入磁盘缓存、WAL 工作面恢复和真实 Range 续传；当前使用方法及保留期限见 [文件管理恢复与续传](file-recovery-resume-2026-10-28.md)。下文性能数字标明历史样本，不替代当前续传回归。

## 使用

1. 运行仓库根目录 `start.py`，它在构建扩展时启动本机下载桥接。也可以单独用 PowerShell 运行 `scripts/start-stream-download.ps1`；交付构建内入口是 `dist/local-download/start-stream-download.ps1`。需要本机 Python 3，不需安装额外 Python 包。
2. Chrome 扩展管理页重新加载 `patmail-extension/dist`，刷新 EASY 来源页与工作台。
3. 使用搜索模板查询，勾选文件后点工作台“下载已选”。ZIP 使用产生这批查询结果时的搜索模板名称；未使用模板时为 `下载文件.zip`。Windows 非法字符被替换，同名下载由浏览器自动另取名。

本机桥接仅监听 `127.0.0.1:42843`，不需要外部中转站、系统服务或注册表安装。脚本检测到同协议服务已运行就复用。仓库 `start.py` 管理自己启动的子进程；独立启动脚本在后台运行桥接。桥接未运行会在开始前明确提示，不会默默退回等待整批服务器压缩。

`start.py` 启动桥接后先确认健康检查通过，运行期间每3秒检查一次，桥接退出后自动重新启动；复用的桥接失联也会恢复。工作台彩虹条仅跟踪下载名称解析，入包和浏览器字节事件不会覆盖或重置这根条。名称解析完成后保持完成状态，最终下载结果仍以浏览器终态为准。

## 实际工作流

```mermaid
flowchart LR
  A[每批40个名称 共用6令牌] --> B[按原顺序交给有界队列]
  B --> C[并行准备文件 有界6文件窗口]
  C --> D[并行FileHandler正文 每份队列256KiB]
  D --> E[ZIP64逐块写入]
  E --> F[扩展后台转发有界字节块]
  F --> G[本机HTTP流]
  G --> H[浏览器一个下载任务]
```

名称生成结果完成一批就能交给下游，无需等全部名称。ZIP 内条目顺序与选择输入顺序相同，保留当前完整下载命名配方和申请号去点开关。路径分隔符、危险文件名会清洗，重名条目加数字后缀，避免覆盖。

命名、DownLoad取句柄与FileHandler正文在同一下载任务内共用6个可归还令牌；读取正文至EOF或取消才释放占用。名称库存少于6个待派发文件时优先补命名，充足时优先准备与读取正文，不固定切分解析/下载份额；流水命名最多6路，其它命名调用仍默认5路。名称队列最多2个可消费批次，最多6个命名工作者各持有一批待交付结果。

正文最多预取6份，每份应用队列以64KiB小块入队，上限256KiB，队列满后停止继续读取。ZIP仍按选择顺序逐条消费，不聚合完整文件或ZIP。最多六份应用队列合计1.5MiB；这个数不包括浏览器内部缓冲、当前网络块、首部校验及ZIP目录。起步、收尾、等待首批名称或缓冲背压时允许不足6路，不会发重复请求凑并发。

本地对照夹具：12份512KiB正文、每64KiB模拟20ms网络等待，旧实现5459ms、正文峰值1；新实现3946ms、正文峰值6；两次ZIP均6293574字节。该数据受运行机器负载影响，不代表实际站点速度承诺。正文与共享业务请求达到六路、按序CRC解包、256KiB队列背压、EOF提前还令牌和阻塞写入取消均有专项回归。

动态令牌浏览器验收通过：81文件ZIP为21,250,590字节，逐条顺序、内容长度和独立Python CRC通过；另以六份正文首块门闩验证六条真实连接同时在途后放行，业务请求峰值6、正文峰值6并成功完成。用户取消和顶层导航仍使原生下载中断；一次查询后修改名称并再次下载回归通过。六路是有可运行工作时的上限，短响应、元数据iframe或ZIP背压下瞬时不足六路属于正常状态。

采用固定版本 `@zip.js/zip.js 2.24.0`，开启ZIP64、关闭Web Worker，使用STORE逐块封装。PDF、已有压缩附件不再二次压缩；这避免浏览器压缩CPU开销，但ZIP体积可能大于原站压缩结果。没有依据承诺任意文件集合总耗时一定更短；主要改善是首个文件不再等全量命名、服务端整包准备，并让传输与命名重叠。

## 原生下载桥接

内容脚本仍在已登录的EASY来源页同源读取业务数据。字节通过有类型的扩展消息交给后台，再以固定本机地址写入流桥接；页面不能指定转发URL。后台为这个任务创建64位十六进制能力令牌，并绑定来源标签页。其它标签不能写入或结束该任务。

桥接只接收扩展Origin的授权请求，不向EASY发请求，不接收任意系统路径。附件和ZIP按不超过256KiB的块持久化到专用缓存目录，读取块不超过64KiB；已确认片段先落盘再ACK。首次GET返回chunked ZIP响应，浏览器自行写入下载临时文件；封存后提供最终长度和Range。最多保留128个任务，暂停缓存保留七天。

`chrome.downloads.download()` 可能等待正文首字节后才返回下载ID，因而创建操作先返回写入令牌，流水开始输出后再取ID跟踪。若先等ID再生产数据，会产生“浏览器等数据、生产者等下载ID”的死锁。

ZIP全部条目和中央目录成功写完后，生产者才关闭HTTP流。最终成功还必须等浏览器报告 `complete`，仅写完ZIP或拿到下载ID都不能报完成。

## 失败与生命周期

- 命名失败、登录失效、HTTP错误、错误HTML页、长度不符、ZIP写入失败都会停止流水，截断HTTP响应；浏览器任务应为 `interrupted`，不能成功关闭残缺ZIP。原附件自身为HTML时允许正常读取该附件。
- 原站单文件DownLoad有实测特例：带“共1个文件…下载失败”文案但句柄有效、FileHandler实际返回完整PDF（1,161,833字节）。与原站GetFile口径一致，不单凭该文案拒绝有效句柄；读取首1KiB检查正文，PDF附件必须有PDF标记，再检查传输长度。空ZIP伪装PDF、空错误正文或HTML仍失败，不把错误包当作PDF条目。
- 用户取消会中止命名和取文件，保留已确认缓存；网络中断则允许生产者继续封存，再恢复浏览器下载。能否复用原记录取决于Chrome的canResume，无法复用时需显式从缓存另存。
- EASY来源页关闭、刷新、顶层导航或工作台离开会暂停仍在运行的流，保留可恢复任务。webNavigation按frameId=0识别真正顶层导航；EASY内部mframe加载不会取消流水。
- 正常运行有状态心跳，失联生产者转暂停；暂停任务保留七天。重新确认同一账号后可继续生产并在封存后使用HTTP Range恢复原下载。完成回执落盘后清理正文缓存，明确丢弃则直接删除任务。
- 旧的整体打包接口保留供既有调用和回归；文件管理工作台按钮默认使用流水，不会把多个独立ZIP直接拼成一个包。

## 验收证据

原生链路的浏览器验收使用真实构建扩展、真实本机HTTP桥接、原生chrome.downloads。业务EASY响应由本地代理夹具提供，不访问真实业务服务器。

- 81个文件（3批命名），以原生字节增长信号放行最后一批名称。全部命名结束前已发出单文件DownLoad，原生下载记录在途字节从524,371增长到1,048,659。
- 最终一个 `华峰官文查询.zip`，21,250,590字节。Python `zipfile.ZipFile.testzip()` 核对81个条目CRC，逐条名称、去点结果、顺序与正文长度一致。
- 浏览器主动取消、真正顶层导航回归通过：原生记录为interrupted，不报告完成残缺包；元数据iframe加载仍可继续流水。
- 完整Vitest：138个文件、882个用例通过；Python桥接5个用例通过，类型检查、构建、动态命名编辑和旧整体下载浏览器回归通过。
- 独立代码复核发现并修复了“后批先成功、前批失败”与有序队列互等的问题；首次命名/正文错误立即停止整条流水，清理阶段的取消或令牌失效不能覆盖原始错误。均有先失败后通过的回归。
- `tests/unit/api/stream-download.test.ts`：241文件流水早启动、原始顺序、共享请求上限5、ZIP解包、HTML/短传输/HTTP失败、重名与路径、取消。
- `tests/stream_bridge_test.py`：写入未结束先读取、有界背压、乱序与重复写入拒绝、跨Origin拒绝、取消必须截断响应。
- `tests/unit/ui/stream-download-background.test.ts`：创建不等待下载ID、来源标签绑定、桥接不可用先失败；`file-search-bulk.test.ts`：结果模板快照不随下载前切换模板变化。

真实站点最终补验也通过：当前账号6个真实文件，使用GetFileName生成名称，走产品内容脚本、实际DownLoad/FileHandler、本机桥接及原生下载；16.705秒完成，最终ZIP6,319,305字节，正文合计6,317,825字节，6条目独立Python CRC通过，观察到5次正字节在途进度，浏览器最终complete。隔离浏览器结束后清理业务临时文件，报告不保留真实名称或正文。原始数字见忽略入库的`test-results/live-native-stream-audit.json`。
