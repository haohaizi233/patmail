# 海牙新申请：材料准备与真实草稿

入口：工作流 → 海牙新申请。

开发与排障参考：[eHague 接口逆向与草稿调用契约](../../API/external-platforms/hague.md)，包含目标站 HTTP 路径、EASY 来源接口、扩展 RPC、原站表单字段和验证边界。

选择总目录，目录内可嵌套多个案件文件夹。案件文件夹名称中的 PO / PA 文号用于识别我方文号（如 `PO数字HAGUE`、`PA数字CN`）；没有该名称时，以 Word 所在目录为边界，默认使用 Word 文件名中识别的文号，未识别时可手动填写。每案需要一份 `.doc` 或 `.docx` 定稿和按 `1.1.jpg` 等编号命名的图片。临时 Word 文件不参与读取。图片按数字排序，不跨案件借用。

同文号嵌套 FIGS 目录归属于外层案件，不另建案件；不同文号的嵌套案件、含独立 Word 的同文号版本继续隔离。章节按 Description / Legends 标题识别，兼容 3、9 等不同编号或不带编号，旧版 DOC 在识别单元格前清理非显示控制符（例如图号后的脚注标记）。Description 在原材料未提供时作为可选空值保留，页面说明未提供，草稿步骤跳过该表单，不编造文本。

页面显示定稿正文、各图与代码对应关系、案号冲突、缺图、重复图号和数量差异。视图表按每组三列 No / Code / Legend 解析；代码 00 要有自定义说明。实际图片与表格不符时，修改原材料并重新选择目录。文号默认使用最近案件文件夹识别的值，Word 文件名不一致仅提示，不阻断处理；有误时直接修改文号。

先登录并绑定 EASY，完成登录状态检测，上传后会自动开始解析、读取与仲裁，无需再次点击。各案在解析就绪后立即精确查询并读取案件、申请人、设计人、优先权信息；完整读取成功后才交给设置中的 Agent。单案失败不会阻断其他案件，可单独重试。停止会终止模型请求和后续案件，已发出的只读查询可能仍会完成。

地址要求：申请人详细地址按原文填写到区名结束；城市、省份、邮编、国家独立。设计人复用申请人地址。申请人英文名称、DAS 等缺失字段不得补造。设计人有中文原名但缺英文名时，按用户授权由同批 AI 仲裁转写拼音（张三 → San ZHANG）；已有英文名优先沿用。

仲裁质量校验：申请人英文名允许直接采用误存于中文名称栏的英文原文；国家统一代码，新加坡省份无来源时留空。设计人数量和顺序由来源固定，明确英文姓/名直接恢复，每位缺失英文姓名进入 AI 拼音转写，返回 sourceName 按中文原名匹配；转写无效或匹配失败时才给一条具体提示。先清理申请号、公告号、证书号等完整引用再识别未知地区，不能把 `35/523,448` 或 `D1,123,008 S` 的逗号片段当成国家；支持“申请国家为……”与“公开方式：立即公开”等备注形式。未知/冲突公开月份为 null，页面显示待核对，不默认 0；正常公开（已申请提前公开）仍按正常公开填写 12 个月，不因办理记录报冲突。按款式限制指定国、另提海牙美国同日递交等条件保留人工核对，不从其他案件推断。历史展会/公告日期不改变已明确的公开方式。已确定的字段不重复报缺失，程序复核后只保留仍然成立的问题。

“导出核对结果”保存各案的解析信息、仲裁结果、来源说明、核对状态及图片文件名，不含原图或 Word，也不含 EASY 原始响应。文件和完整响应只保留在当前页面内存，关闭页面后重新选择材料。

优先权直接映射 `priority_no`、`priority_date_dd`（或 `priority_date`）、`priority_country_id` 和 `access_code`，不使用 `priority_id` 或 `seq` 推测申请号。原始中国申请号如 `111` 不可用时自动生成带校验位的草稿占位号，保留 `originalNumber`，标记 `generated` 和 `requiresReview`，明确要求人工审核替换，不冒充真实在先申请。申请号结构参考[国家知识产权局标准](https://www.cnipa.gov.cn/art/2003/7/14/art_526_145959.html)。

案件状态：解析材料 → 待处理 / 材料待修正 → 读取知易通 → Agent 仲裁 → 待核对结果 → 已核对；异常单独标记，停止后保留已经读取的原文，批量继续不会重读已取得的数据。首次上传按“解析完成 / 读取完成 / 仲裁完成”三个真实步骤计数，继续处理按读取和仲裁计数；失败计入已处理数，与成功数分别显示。页面复用彩虹进度组件，但使用独立进度，避免覆盖其他工作流。

英文地址固定读取 `contact_address_en`，城市和省份分别按 `city` / `province` 核对英文名称，不能使用中文地址或把合作区当成省。设计人卡片明确展示复用后的完整地址。

邮编中的 `/`、`-`、`N/A` 等占位符按缺失处理；只能采用本案有效邮编字段，或从截断前的完整英文地址末尾恢复明确邮编，不按城市猜测。中国、新加坡邮编校验六位数字，新加坡保留前导零；楼栋号不能作为邮编。国家字段先归一代码，忽略占位符；字段缺失时可采用英文地址末尾明确国名，不采用模型无来源的国家猜测。邮编或国家字段与地址存在冲突时保留来源字段并提示。设计人继续复用第一申请人；每位申请人的缺失和冲突都参与最终复核，旧结果中的无效邮编也会在写入前拦截。

指定清单逐段复核，公开时间优先按案件备注“公开情况”后的客户要求（兼容“公开方式”“公开时间”）：正常公开或 12 个月公开选 Publication 12 months after the date of international registration；立即公开选 Publication immediately after the recording of the international registration；其他明确月份选 Publication at a chosen time 并选择对应月份。历史办理、展会和其他申请的公开描述不覆盖明确的本案要求；多段指定清单不一致或多条明确的本案公开要求不同才标记冲突，不只取第一段，也不直接合并。另案同日递交不自动追加为海牙指定国，按款式排除国家的条件单独保留一条警告。公开月份允许 0 或 2–30 个月，实际目标站选项仍以所选缔约方为准。

真实草稿入口：连接并验证 eHague 后，可选择“填写并保存本案草稿”或“批量填写并存草稿”。先在本地检查全部申请人、设计人英文姓名、地址、指定国、优先权及图纸映射，缺项时展示具体原因。所有申请人均进入草稿，设计人地址复用第一申请人。缺少英文设计人姓名时由 AI 按中文原名转写拼音，标记来源，可在工作台审阅修改。当前自动填表配置适用于中国法人申请人，国籍、住所、营业所、惯常住所及 ACP 按递交说明填 CN。

创建步骤：English / New application → 申请人 → 代理机构 → 指定缔约方 → Locarno 与逐项设计 → 图纸逐张上传与 Legend → Description → Creators → Priorities → Publication → Signature / 我方文号 → Summary PDF → 返回编辑器 Close / Yes 保存至 Draft(s)。不进入 Payment/Validation 或提交。Locarno 小类读取产品表第 4 列，第 2 列是图纸数量，不可混用。Legend 按名称匹配站点选项，不能复用 Word 数字代码；自定义 Legend 填 Other type of view 及原文。

多记录操作：N 位申请人执行 N 次 Add Applicant，每位单独填写并 Save，保存后核对记录数再添加下一位。图片前缀 `1.x`、`2.x` 等分别对应产品表同编号的设计；每组单独 Add design、填写本组小类和产品、上传本组图片并设置 Legend、点 Ok 保存，再开始下一组。组内上传计数从零开始，不将多组图片并入第一项设计。双申请人、双设计（共 16 图）的隔离浏览器回归约束上述调用顺序。

每次写入均固定标签页、文档和 WIPO reference，并等待原站回执。案间可选 1–6 路独立标签页；每案内部串行，图片逐张按自然数字顺序上传，超过 10 张通过表格分页核对，避免 1.10 排序问题。目标站支持不超过 2MB 的 JPG/TIF；本地预览可用 PNG，但写入前须转换。DAS 不符合四位格式时不编造，草稿中留空并保留原值及人工补充提示；自动生成的优先权号仍只作草稿占位。

写入检查点和 WIPO reference 保存在本机扩展存储，导出核对结果也包含这些回执。停止等待当前步骤回执后生效；已确认的边界可继续，结果不确定的写入不自动重试。用户须核对该步是否已执行，再选择继续下一步或允许重试。材料字段变化会阻止复用旧检查点；最后保存还需在 Draft(s) 列表精确核对该 WIPO reference。

Summary 使用原站页面打印样式生成 PDF，保存到原浏览器下载目录下 `PatMail/Hague/我方文号/Summary-WIPO编号.pdf`，并可打开所在位置。扩展新增 `debugger` 权限用于临时 `Page.printToPDF`，结束即断开，不设置下载行为。该权限不能声明为可选权限，见 [Chrome permissions 文档](https://developer.chrome.com/docs/extensions/reference/api/permissions)。只读 CDP 日志服务不承担打印或业务操作。

登录会话：工作台右上角复用登录会话卡片。先打开 WIPO eHague 并完成原站登录，再选择标签页“连接并检测登录”。只读访问受保护 portfolioManager.xhtml，要求服务器返回已登录案件列表标记；仅有 WIPO 标签页或登录页面不算验证通过。验证时校验标签页与文档未切换，不读取 Cookie、密码或令牌，不写申请。

未验证时仅允许本地文件解析，各案进入“等待 eHague 登录验证”，不会读知易通或调用 AI。验证成功后自动继续；开始处理前重新确认过期的验证，切换、关闭或导航标签页后使验证失效。eHague 会话与顶部 EASY 连接分别管理。

海牙仲裁接入 AI 助手：与 PCT 共用 AgentDock → AgentChat 的串行任务通道，助手会话内保留批次及回复，海牙页面不直接调用 LLM。海牙通过独立的 `hague-filing-arbitration` 技能路由使用海牙系统提示词，不使用 PCT 的 `plain: true` 收件人仲裁规则；模型输入仅包含本批材料，不注入历史对话和长期记忆，已保存记忆仍保留。已取数案件自动入队；每批最多 3 案，按压缩材料约 20,000 字符控制，长材料自动缩小批量。第一批可立即开始，运行期间就绪的案件合并进入后续批次，不阻断取数流水线。返回按 caseVolume 唯一匹配，缺失/重复文号只影响对应案件。停止或清空队列会向工作台返回状态，不遗留等待。未知回复最多修正一次，确定的原始字段校验仍保留。

批量草稿调度：选择“草稿并发”1–6 路后点击“批量填写并存草稿”。默认 1 路，多路标为试运行。新案打开后台 portfolio 工作页并验证登录；每案完整执行原步骤链。成功后复用该路已回到 Draft(s) 的页面处理下一案；失败或未确认页面保留，不导航覆盖。空闲路立即补案。已保存案件不重复创建；材料无效、结果不确定、重复文号和共用检查点标签页的案件逐案显示跳过原因。停止不再领取新案，已发出步骤等待回执；登录失效停止整个队列。顶部统计真实步骤、运行路数、成功/异常/跳过，案件列表保留各案检查点。

预检查未通过显示“暂未填写”，与“草稿执行失败”分开；两者都在详情显示具体原因，不把邮编缺失、图数不符或当前未支持的资格配置说成 Cookie/登录异常。Chrome 注入参数不允许数组包含 undefined，可选 WIPO reference 不存在时省略该参数，不能传 `[command, undefined]`；首次 inspect 因此失败不代表登录失效，也没有开始创建申请。
