# 海牙新申请工作流操作说明

阶段流程图与判定表见 [海牙新申请工作流](workflows/海牙新申请.md)，工作台“流程说明”使用该文件；本文保留详细操作参考。

更新：2026-11-13。入口：**工作流 → 海牙新申请**。页面内“流程说明”查看新版阶段流程；本文保留详细操作参考，“开始使用”进入工作台。

本工作流将本地定稿 Word、图纸和知易通案件信息整理为 eHague 草稿，生成 Summary 文件，最后交由用户审核。默认填写方式为**接口链**，批量草稿默认 **6 路并发**，可调整为 1–6 路。

## 1. 一次完整操作

1. 在工作台顶部连接正确的 EASY 大客户或中小客户系统，确认当前账号。
2. 打开 WIPO eHague，完成原站登录，再回到海牙工作台连接并检测登录。
3. 点击“选择总文件夹”，选中包含全部案件材料的目录。
4. 等待逐案解析、取数和仲裁，查看左侧案件状态，核对右侧材料与结果。
5. 确认填写方式、草稿并发和导出格式；默认接口链、6 路、单个 PDF。
6. 点击“批量填写并存草稿”；也可以先对单案点击“填写并保存本案草稿”。
7. 等待完成弹窗，查看成功、异常、跳过及逐案审核提醒。
8. 打开下载文件和 WIPO 草稿，完成最终人工审核。

“保存草稿”“PDF 已下载”和“正式递交”是不同结果。本工作流处理草稿与导出；正式递交和付款应在原站按业务流程另行完成。

## 2. 开始前准备

### 2.1 账号与页面

| 项目 | 准备方式 | 常见误区 |
|---|---|---|
| EASY | 在顶部连接并检测正确系统和账号 | 同一文号不一定存在于当前大客户/中小客户系统，查询不到时先核对系统 |
| WIPO eHague | 在原站完成登录及必要的二次验证，再连接标签页 | 仅打开登录页不代表已登录 |
| AI 助手 | 在设置中配置可用的 Agent，保持助手可接受任务 | 反复点击不会加快已排队的仲裁 |
| 浏览器 | 保留海牙工作台和绑定的 WIPO 标签页 | 运行中刷新、关闭或切换登录账号会影响续接 |
| 下载 | 确认浏览器下载目录可写、有足够空间 | 看到进度条结束前不要移动或删除正在生成的文件 |

EASY 用于读取来源案件，WIPO 用于创建目标草稿，两者登录状态分别管理。

### 2.2 当前适用材料

自动填写目前支持中国、新加坡法人申请人配置。新加坡未提供省份时可留空。自然人、其他国家或资格来源不足的案件，会显示具体核对原因；不能仅更改国家代码绕过检查。

新加坡申请人的资格国家和 ACP 按本案来源国家形成草稿候选，完成后仍需审核国籍、住所、营业所和惯常居所等信息。

## 3. 如何整理文件夹

推荐每案一个文件夹，里面放一份定稿 Word 和全部编号图纸。总目录可以嵌套客户文件夹。

```text
海牙本批材料/
├─ 客户甲/
│  └─ PO0000001HAGUE-产品名称/
│     ├─ 定稿.docx
│     ├─ 1.1.jpg
│     ├─ 1.2.jpg
│     └─ 1.3.jpg
└─ 客户乙/
   └─ PA0000002CN-HAGUE-产品名称/
      ├─ 定稿.doc
      ├─ 1.1.jpg
      ├─ 1.2.jpg
      ├─ 2.1.jpg
      └─ 2.2.jpg
```

以上文号和文件仅为格式示意。

### 3.1 案件识别

- 从最近的有效案件文件夹识别我方文号，使用 P 前缀、HAGUE 后缀的文号。
- 文件夹没有有效文号时，可从 Word 文件名识别；仍未识别时，在详情“我方文号”中补充。
- Word 文件名和目录文号不一致时会提示，应核对后再处理。
- 同文号 FIGS 等图纸子目录可归入外层案件；不同文号、独立 Word 或材料版本会分别识别。
- 同一文号存在多个版本时，先保留本轮需要的唯一版本，再选择目录，避免重复创建。
- Word 临时文件（例如以 ~$ 开头）不参与识别；每案仍须只有一份有效定稿。

修改我方文号会清理该行当前来源、仲裁和草稿关联。已有草稿时应先记录 WIPO reference 并核对归属，不要把更换文号当成续接方式。

### 3.2 Word 要求

支持 `.docx` 和旧版 `.doc`。每份文档应包含：

| 内容 | 用途 |
|---|---|
| Locarno 大类 | 选择原站大类 |
| 产品表 | 每项设计的编号、图纸数、产品名称及小类 |
| Description | 有来源时填写；没有时保留空值并跳过说明步骤 |
| Legends / 视图表 | 对应图号、视图代码和必要的文字说明 |

Word 不超过 20 MiB。旧版 DOC 在本地解析，不需要先启动 Office；损坏或无法解析时，检查原文件是否完整，必要时重新保存为规范 DOCX 后再选择。

产品表第二列是图纸数，第四列是小类。设计编号应从 1 连续编号，不能每行都写 1。不同版本表格的视图代码可能不同，系统优先读取本案文档的对照表。

### 3.3 图纸要求

- 用 `设计号.图号` 命名，例如 1.1、1.2、2.1。
- 每项设计独立分组，1.x 不与 2.x 混用。
- 图片按数值顺序处理，1.10 排在 1.2 后。
- 目标站上传使用 JPG/JPEG 或 TIF/TIFF，单张不超过 2 MiB。
- PNG 可在本地预览，但创建草稿前需准备受支持的上传格式。
- 产品表数量、视图表图号和实际图片须一一对应；重复编号、缺图、多图或缺少视图说明都需处理。
- 自定义视图代码 00 需要文字说明，不能只填代码不填含义。

若原 Word 多行编号全为 1，且各行产品/小类相同、图纸组和数量完全对应，详情可能显示“按图纸分组修正重复设计编号”。核对后点击才修正草稿使用的编号，原 Word 文件不变；修正说明会保留并在完成后提醒。其他不明确的编号冲突应修改原材料。

## 4. 连接 WIPO eHague

在海牙页面右上角的 WIPO eHague 连接区操作：

1. 点击“打开平台”，在原站完成登录。
2. 回到工作台，点击“查找标签页”，选择正确的 WIPO 页面。
3. 点击“连接并检测登录”。
4. 检测通过后再开始取数、仲裁和草稿填写。

检测会读取受保护的案件列表，判断当前会话是否可用。只存在标签页、原站显示某个页面或请求返回 200，都不等于验证通过。

如果先选择了文件夹，但尚未验证 WIPO，工作台可以先解析本地材料，案件会显示“等待 eHague 登录验证”；验证通过后继续处理。验证过期或标签页发生变化时，开始后续操作前会重新确认。

若提示无法确认登录：先回到原站检查登录/二次验证是否完成，再回工作台重新查找和检测。已有草稿编号时先保留编号，不要直接新建替代草稿。

## 5. 前端界面怎么使用

### 5.1 顶部按钮与选项

| 控件 | 操作含义 |
|---|---|
| 选择总文件夹 | 导入本批全部材料；选择新目录会重建当前案件列表 |
| 读取知易通并批量仲裁 | 处理尚未得到结果的案件；停止后可显示“继续处理剩余案件” |
| 停止后续处理 | 停止后续解析/取数/仲裁任务；已发查询可能仍会返回 |
| 导出核对结果 | 下载 JSON，保留本页材料解析、仲裁、提醒和草稿状态用于核对 |
| 填写方式 | 默认接口链，可选页面填写 |
| 草稿并发 | 默认 6 路，可选 1–6；1 路表示串行 |
| 导出格式 | 接口链可选单个 PDF 或流式 ZIP，默认单个 PDF |
| 批量填写并存草稿 | 为当前可处理、尚未保存的案件创建或继续草稿 |
| 停止后续写入 | 不再领取后续案件，等待已经发出的当前步骤回执 |
| 已存草稿打包 ZIP | 将当前列表中已保存且有编号的草稿 Summary 汇总导出 |

运行时部分控件会禁用，防止处理中修改材料、并发或模式。等本轮结束后再调整。

### 5.2 默认 6 路的含义

最多同时处理 6 个案件，每个案件内部仍按顺序填写。某路完成后，会立即领取下一案；少于 6 个可处理案件时，实际运行路数也会更少。

- 草稿并发不会把同一案的申请人、图纸和优先权交错写入。
- 仲裁助手仍按自己的队列串行处理，6 路草稿并发不等于同时发起 6 个 AI 任务。
- PDF 生成也有独立队列，因此尾段可能出现多案等待导出。
- 单案“填写并保存本案草稿”只处理该案，不会因为默认 6 路额外创建案件。
- 网络或电脑负载较高时，可以在下次开始前调低并发。

### 5.3 两种填写方式

| 方式 | 使用方式 | 异常时 |
|---|---|---|
| 接口链（默认） | 通过绑定的已登录 WIPO 页面处理各案，减少工作标签页 | 对可核对步骤自动读取回执，证据不足则暂停该案 |
| 页面填写 | 批量时打开独立工作标签页；单案使用所选标签页 | 保留异常页供人工检查 |

已有草稿检查点要使用原执行方式继续，不要在已有进度后随意切换方式。

### 5.4 案件列表、详情和进度

左侧案件列表显示文号、目录、状态和材料问题数。点击切换案件，右侧查看该案的 Word 解析、图纸、仲裁结果和 eHague 草稿进度。列表与详情分别滚动。

顶部公共进度条显示本批处理数量和阶段。草稿填写时显示成功、异常、跳过、运行路数和已确认步骤数；例如运行路数降为 0 时，应结合完成提示判断本轮是否已结束，不能只看百分比。

不同案件的图纸和设计数量不同，步骤数并不相同。某案进入异常后，已确认步骤不会冒充整案成功。

## 6. 解析、取数与仲裁

选择目录后，系统逐案解析，读取当前 EASY 系统中精确文号对应的案件、申请人、设计人、优先权和备注，再交给海牙仲裁。

单案读取失败不等于全批失败；先查看该案原因，再使用“读取并仲裁本案”或“重新读取并仲裁本案”。重新仲裁会更新本案来源与结果，已有草稿进度时应先确认材料是否变化。

常见状态：

| 状态 | 含义与处理 |
|---|---|
| 解析材料 | 正在读取 Word 和图纸信息 |
| 等待 eHague 登录验证 | 先连接并检测 WIPO，再继续 |
| 待处理 / 读取知易通 | 已有本地材料，等待或正在读取来源 |
| 等待 AI 仲裁 / Agent 统一仲裁 | 已取数，等待助手处理 |
| 材料待修正 | 查看缺图、编号、文号或表格等问题，修正后重新选择材料 |
| 待核对结果 / 已核对 | 仲裁已返回，可逐项查看 |
| 处理失败 / 已停止，可继续 | 看具体错误，处理后继续相应阶段 |

“知易通未找到案件”优先检查文号和所选系统；不要用其他案件的结果填补缺失来源。

## 7. 创建前逐项核对

### 7.1 材料与视图

核对产品、小类、设计数量、每组图纸数和各图 Legend。点击缩略图可放大，支持上一张/下一张、缩放、适应窗口、方向键和 Esc；关闭后回到对应缩略图。

原材料没有 Description 时可以留空，系统不代写描述。视图代码与文字冲突时，应按本案定稿确认，不要套用另一份表格的代码。

### 7.2 申请人和地址

核对英文名称、详细地址、城市、省份、邮编和国家。界面分开展示这些字段，详细地址不要再混入重复的城市/省份。

邮编缺失时可留空，会进入完成提醒；现有非空邮编仍须有效。系统不依据城市编造邮编，也不会借用其他案件邮编。国家字段或地址来源冲突时，要回到来源核对。

申请人英文名称等关键来源不完整时，应补充可靠来源，再重新读取仲裁。当前界面不是所有申请人字段的任意编辑器。

### 7.3 设计人

核对人数、顺序和姓名。已有英文姓名优先采用来源；仅有中文原名时按授权转写拼音并标明来源。设计人的地址复用第一申请人。

展开“补充设计人英文姓名”可在尚未开始草稿前修改名和姓。已有草稿后该输入会锁定，避免改字段后继续沿用旧步骤。

### 7.4 指定国与公开时间

按本案客户备注核对完整指定清单，欧盟显示为 EM。另案美国同日递交、按款式排除国家等内容会单独提醒，不能自行理解为所有设计都追加同一国家。

公开时间显示为明确月份：正常公开为 12 个月，立即公开为 0 个月，其他明确要求显示相应月份。“待核对”时先补全来源，不要把未知月份当立即公开。

### 7.5 优先权与 DAS

核对在先申请号、日期、国家和 DAS。数据库 ID/序号不能当成申请号。

出现“自动生成的草稿占位申请号”时，原始值仍会显示，保存后必须审核替换；这个候选值不能当成真实在先申请号。DAS 不符合四位格式时，草稿留空并提醒，原值保留用于核对。

日期是否能保存，应结合原站实际校验和回执判断，不单凭日历控件显示范围改动来源日期。

页面的“已逐项核对材料、视图、地址和仲裁结果”用于记录核对状态；有待审提示时可能无法勾选。提示是否阻止创建，以“eHague 草稿”区域的具体原因和按钮状态为准。

## 8. 批量创建与单案处理

### 8.1 批量创建

确认默认接口链、6 路并发及导出格式后，点击“批量填写并存草稿”。系统逐案执行：

准备申请 → 创建并取得 WIPO 编号 → 申请人/代理机构 → 指定国/大类 → 各设计和图纸 → 说明/设计人/优先权 → 公开/签名 → Summary 与下载 → 保存草稿。

创建后会先保留可恢复的草稿编号，后续每步保存进度。初始编号存在不代表整案已完成；以最终“草稿已保存”和列表核对为准。

已保存案件不会重复创建。材料不完整、重复版本或无法安全续接的案件会显示具体原因，不影响其他可处理案件继续。

### 8.2 单案按钮

| 按钮 | 使用场景 |
|---|---|
| 填写并保存本案草稿 | 本案尚未建立草稿，可先验证单案处理结果 |
| 继续当前草稿 | 有已确认进度，继续原 WIPO 编号 |
| 核对并恢复当前草稿 | 接口链结果不确定，先读回原站再决定能否继续 |
| 草稿已保存 | 已完成，不能再次创建 |
| 打开导出文件所在位置 | 查看该案关联的浏览器下载文件 |

同一案已有编号时，优先续接原草稿。不要通过更换目录、文号或执行方式绕过异常。

## 9. 自动恢复与人工接管

指定国、大类、优先权及最终保存出现不确定回执时，接口链会按原编号重新读取原站状态。能证明已完成则推进；能证明可安全重试则恢复一次；仍无法确认则保留暂停。

每一步的自动恢复次数会保存，刷新不会重置。恢复记录会进入审核提醒。创建、图纸上传、打印等无法充分判断是否已执行的操作仍需人工核对，不能把超时当成“没有执行”。

### 9.1 无法自动确认时

1. 记录详情中的 WIPO reference、当前阶段和错误。
2. 打开原站同一编号，检查该步骤的实际记录、字段和数量。
3. 若确认本步已完整完成，点击“本步已完成，继续下一步”。
4. 若确认本步未执行，点击“本步未执行，允许重试”。
5. 再点击继续/恢复按钮处理后续步骤。

这两个确认按钮会调整检查点，应以原站事实为依据；拿不准时先保留暂停，不要反复切换两个选项。

### 9.2 常见问题

| 提示或现象 | 建议处理 |
|---|---|
| 暂未填写，查看原因 | 预检查未通过；先看材料、来源或配置原因，不一定是登录问题 |
| 指定国不一致 / 不支持指定国 | 查看本案清单和原站实际选择，等待自动核对或人工确认 |
| 优先权记录数不符 | 检查是否已经保存对应记录，避免重复添加 |
| 草稿记录尚未确认 | 按编号检查 Draft(s)，注意可能在后续页；不能据此新建替代草稿 |
| 材料或字段在存档后变化 | 核对旧草稿和新材料差异，再决定后续处理，不能直接沿旧位置写入 |
| 旧检查点缺少材料指纹 | 按原站事实人工核对，不自动猜测材料是否相同 |
| 多个案件指向同一 WIPO 编号 | 核对案件归属和检查点，不能并发写同一草稿 |
| 登录失效 | 回原站登录并重新检测；保留原编号再续接 |
| 进度停住 | 查看运行路数、当前阶段和错误；导出队列、等待回执和本轮已结束是不同情况 |
| PDF 下载中断 | 先查看浏览器下载列表与草稿状态；已保存草稿可单独重新导出 |

## 10. 完成弹窗与最终审核

本轮结束会弹出“草稿处理完成”，显示成功、异常和跳过数量，并按案件列出待审核事项。例如：邮编留空、SG 资格候选、编号修正、姓名转写、优先权占位号、来源条件冲突或自动恢复记录。

点击“我知道了”关闭后，案件列表和详情仍保留状态。异常不表示其他案件未成功；应分别查看各案 WIPO 编号、最后确认步骤和下载文件。

最终至少核对：

- WIPO reference 与我方文号对应正确。
- 所有申请人、设计人、名称和地址符合本案来源。
- 指定国及按款式的条件正确。
- 设计数量、产品、小类、每张图及 Legend 正确。
- Description、优先权原始信息、DAS、公开时间和签名正确。
- 占位号、转写、留空项及材料修正提示已处理。
- Summary 文件可打开，原站同编号草稿可在 Draft(s) 找到。

## 11. PDF、ZIP 和核对结果

### 11.1 创建时的导出格式

接口链默认“单个 PDF”，为每案生成 Summary 并下载。选择“流式 ZIP”时，使用该案本次生成的 Summary 导出 ZIP；这不等同于把整个批次合成一个总包。

整个批次需要一个 ZIP 时，待草稿保存后使用“已存草稿打包 ZIP”。

导出文件保存至浏览器下载目录，实际位置以浏览器下载记录及“打开导出文件所在位置”为准。页面填写模式的 PDF 使用 PatMail/Hague/我方文号 子目录；接口链使用统一原生导出流程，不应把某个固定路径当成所有模式的共同约定。

### 11.2 已存草稿打包 ZIP

只处理当前列表中“已保存”且有 WIPO 编号的案件。重新检测登录后，逐案读取既有草稿 Summary，汇总为含多份 PDF 的 ZIP；不会因此创建新草稿。

打包期间顶部显示 PDF 生成/打包进度，浏览器确认下载完成后才显示完成。遇到错误会中止，查看提示后处理；不要把缺件或中断文件当成完整交付包。

### 11.3 导出核对结果

“导出核对结果”下载“海牙申请核对结果.json”，包含各案路径、文号、解析结果、来源判断、提醒及草稿状态，用于留存和排查。

JSON 不是原始 Word/图纸备份，也不是当前已提供的自动导入续跑文件。应保留原始目录，不能导出 JSON 后删除材料。

## 12. 停止、刷新与后续批次

- 点击停止后，等待当前已发操作返回；停止不是撤销已经写到原站的记录。
- 运行中不要刷新工作台、重新加载扩展、关闭绑定页面或切换账号。
- 页面刷新后，原始 File 对象和案件列表可能丢失；本地草稿检查点与所选材料不是一份数据。
- 续接时重新选择原材料目录、连接同一账号和原执行方式，再按已有检查点核对。材料变化或目标标签页变化可能需要人工处理。
- 选择新文件夹会重建列表；开始下一批前，先保存上一批核对结果、记录异常编号并确认下载完成。
- 安装或编译新版后，等待当前批次完成，再重新加载扩展启用新代码。

## 13. 给维护人员的入口

维护人员先看本机 CDP 状态和最近日志，再沿请求/进度/任务编号关联；必要时使用原生 CDP 核对。完整协议和算法分别见：
