# 文件管理工作流

工作流里选「文件管理」进入这一页。适合没有固定 PCT 表格、按文件批量发文的客户。

| 控件 | 作用 |
|---|---|
| 选择客户 | 选一个绑好了文件管理配置的客户 |
| 查询条件 | 按客户保存的查询条件查出文件，通常按文件描述或日期 |
| 发文映射 | 文件描述对上发文类型，映射规则在发文映射页维护 |
| 收件人 | 案件联系人 |
| 抄送 | 默认发件人和商务 |
| 审核人 | 默认审核人 |
| 标题 | 标题模板 |
| 正文 | 发文页邮件签名下拉里的格式 |
| 发明人 | 所属部门包含研发本部时，文件描述右侧写入全部发明人，顿号分隔 |
| 提交 | 创建发文并提交给默认审核人 |

文件管理路径的「完成事项」保留草稿原值，不会像 PCT 提醒那样自动勾上本封的处理事项。

## 账单识别与「只选所有账单」集合语义

### 1. 账单命名规范与优先级识别机制

账单标准命名结构：  
**`[账单号] + [我方案号] + [事项] + [账单日期] + [可选版本后缀] + [扩展名]`**  
例如：`INVSG260800245 PA2511528CN-ID 实审账单 20260811（更新）.pdf`

算法识别严格执行三级优先级，彻底解决账单号与案号的错位问题：
- **优先级 1（明确提示）**：优先使用行内 `caseVolumeHint`，按完整 token 边界匹配并容忍尾随连接符（如 `PA2631884CN-US-`），禁止将极短数字/字母片段误切；
- **优先级 2（标准 PA 案号模式）**：无有效提示时，优先匹配业务核心 `PA` 开头案号（如 `PA\d{4,}[\w-]*`），避免将 `INVSG...`、`BILL...` 等账单号误当案号；
- **优先级 3（保守通用格式）**：排除已知账单前缀（`INVSG`、`INV`、`BILL`、`CREDIT` 等），保守匹配。若无法可靠定位则返回未识别；
- **日历日期有效性**：严格校验年月日合法性（包括大小月和平闰年 2 月），排除 `20260231` 等伪日期；
- **变异容错**：自动剥离末尾版本修饰符（`（更新）`、`(2)` 等），支持特殊空白符（`\u00A0` 等），案号前置变体需在事项中明确带有“账单”或“退款/Credit Memo”字样才予识别，坚决排除通知书、发票、费用清单。

### 2. 「只选所有账单」的过滤式集合语义

- **语义定义**：只保留当前查询结果范围内识别为账单的文件，**替换**已有选择。
- **清除旧非账单**：操作触发时自动清除先前勾选的非账单文件，最终选中的每个文件均必须满足 `isBillPatentFile(file) === true`。
- **多页容灾补齐**：若多页并发拉取时部分页面失败，显示失败页数并保留已确认账单；点击「重试没读到的页」进行二次补齐时，依然仅追加账单文件，绝无非账单污染。
