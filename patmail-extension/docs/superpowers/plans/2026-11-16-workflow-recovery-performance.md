# 工作流刷新恢复与六路调度

用户选择：刷新后自动核验并继续未完成批次。已授权的业务流程保持不变。

1. 工作流导航及编辑状态写入现有 WAL，恢复完成后再启用持久化监听。
2. 海牙材料以 Blob 保存到 IndexedDB，WAL 保存工作台清单和批次运行代号；文件先落盘，清单后提交。每步原有检查点仍须写入完成后才发送业务请求。
3. 运行批次持有跨页面 Web Lock；刷新后先等待后台旧请求安静，再验证登录及按原运行代号读取检查点。已保存案件计入成功，未确认分配不得重新创建。
4. 合并诊断显示洪峰、降低可选诊断快照写入频率；不丢弃业务回执或延迟关键检查点。
5. 六路队列按预计剩余工作量稳定排序，长案件先开，空闲路立即补位；不改变单案步骤和独占安全门。
6. 单元测试覆盖恢复文件、运行代号、旧请求等待、并发边界和刷新；构建、类型检查及原生 CDP 验证工作台刷新。

进度：现有真实界面已观察到 14/14、637/637、0 异常；原生只读网络探针已记录 6 个同时在途的业务 POST。此前修复为当前基线，不重复创建验收草稿。

实现完成：导航 WAL、材料 Blob 仓库、运行代号、浏览器全局锁、旧请求安静等待、同代已完成计数、150ms 进度合并、250ms 诊断通知、3s 可选诊断快照与单个待写快照背压、HTTP 剩余工作量优先调度。

验证：最终全量 287 文件 / 1997 测试通过；定向 31 项恢复与并发回归通过。构建/类型检查与变更文件 ESLint 通过。原生 CDP 在独立插件标签页导入一案后刷新，子页面、Word、六张 1890×1890 图纸、历史保存检查点全部恢复。原四件已停止批次的旧标签页保留。后台新 action 需要重载扩展生效；不把单纯页面刷新当成后台已升级。

限制：未为验证刷新而在原站重复分配新草稿；实际写入中断后的续跑以故障测试验证，现场 CDP 验证的是工作台及材料恢复。
