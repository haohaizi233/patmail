# Streaming download implementation plan

**Goal:** GetFileName 与单文件 DownLoad 流水衔接，生成一个以查询时搜索模板名命名的 ZIP，并在浏览器原生下载记录中持续显示字节。

**Architecture:** EASY 内容脚本持有会话并生产名称/文件流，成熟 ZIP64 写入器按背压输出。受控扩展后台创建本机流桥接任务并调用 chrome.downloads；标准库 Python 服务仅绑定127.0.0.1，使用不可猜测令牌与有界队列转发字节，不读取业务源、不聚合整包。沿用仓库 start.py 启动；提供独立启动脚本。未启动时明确提示，不能默默退回等待整包。

**Spec:** 用户已同意研究文档中的前端流水单ZIP方案，并明确要求原生下载与搜索模板包名。当前包名取本次查询成功时的模板快照，空模板为下载文件；Windows非法字符清洗，重复下载由浏览器自动另取名。

## Constraints and decisions

- 原工作区有用户并行编辑；只修改下载相关代码与启动入口，不提交或覆盖其他改动。
- 名称最多5路、每批40；流水共享最多5个业务请求的预算，给同源其它请求留余量。队列最多2批，名称顺序按原输入固定。
- 下游文件单路读取；取消/失败中断浏览器流，禁止成功关闭残缺ZIP。ZIP64库负责大文件及CRC，文件名防路径穿越与重名。
- 浏览器下载任务与桥接令牌绑定；只有扩展页面/受信EASY内容脚本能够发起，不能开放任意URL下载。
- 本机服务不安装系统服务、不改注册表；start.py管理子进程生命周期。启动器允许复用已运行的同协议服务。
- 发文等现有调用保持原命名接口；新增批次回调允许背压，不改变它们返回完整数组的口径。

## Tasks

- [x] 模板包名：先写清洗和查询模板快照回归，贯通消息校验、内容脚本、下载名称。
- [x] 本机桥接：Python集成测试覆盖先读后写、持续分块、容量上限、乱序拒绝、取消断流、非扩展来源拒绝；实现服务和启动入口。
- [x] 流水核心：测试五路命名乱序回填、批次消费早于命名结束、背压、下载取消/长度/HTML错误、重名与ZIP解包；实现ZIP64流和本机写入器。
- [x] 产品接入：后台创建/取消桥接下载，内容脚本流水与原生终态跟踪，工作台显示同时命名和真实字节；对齐receivedBytes协议。
- [x] 验收：类型检查、全量测试、构建、真实扩展浏览器夹具；原生in_progress在生产未结束前bytesReceived增长，最终一个模板名ZIP且独立Python解包CRC通过。文档记录运行条件和失败边界，独立代码复核。

## Progress

- 原生扩展虚拟URL验证：claim控制后fetch可流式，但chrome.downloads仍NETWORK_FAILED；采用本机HTTP桥接。
- 138文件882用例及Python5用例通过。81文件21,250,590字节ZIP，独立Python CRC通过；原生真实字节在末批命名放行前增长，取消和顶层导航会中断。
- 独立复核P1乱序失败死锁已以onFailure立即传播修复；两层清理均保留首次原始错误，三种回归先红后绿，复验通过。
- 实站补验修复内部mframe加载误取消；单文件失败提示但PDF正文有效按原站句柄规则处理，新增类型/空正文回归。最终真实6文件16.705秒、6,319,305字节ZIP、原生complete、6条目CRC通过。独立复核通过。
