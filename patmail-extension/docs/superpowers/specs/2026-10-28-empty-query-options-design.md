# 三个查询表空选项呈现设计（待确认）

## 问题和证据

`TreeOptionSelect.vue` 即使roots为空也允许show，仍显示搜索、查询、清除、确定、全选。原站确认ApplyTags=null时，插件只把自由文本换成了无用的空菜单。

字典service把接口失败写成sources[name]=null，后续适配和缓存回退可能混淆“成功返回空”“失败未读到”“旧缓存”。`rememberChoices`只保留非空列表，也不足以表达明确空数据导致的旧选项失效。

## 方案

- 隐藏无选项字段：表单位置会变化，也可能让用户找不到原站对应条件，不推荐。
- 允许自由文本：该字段提交的是ID，文本不能构造有效查询，不采用。
- **建议：保留字段标签，用不可展开的状态文本替代空下拉；有选项时仍使用原来的树/复选下拉。**

## 行为

1. 原站成功明确返回空：显示“当前账号未配置专利标签”等字段级文案，无下拉箭头、搜索框、全选或确定按钮；不伪造选项。
2. 请求尚未完成：显示“正在读取选项…”，不提前判为原站未配置。
3. 请求失败：显示“选项读取失败”和重试入口；不能被缓存标记成成功空结果。每个数据源的加载状态贯通service、适配器、缓存和UI；仅预期字段明确为null或空数组属于成功空，字段缺失或结构异常属于失败/无效响应。
4. 其它人员、部门等控件同样按真实状态处理，不能一律用“未配置专利标签”。搜索已有树但无匹配属于另一状态，保留搜索与清除搜索能力。
5. 明确空响应写入空值墓碑，使该字段所有page/static/saved回退同时失效，不展示过期缓存为可选项；失败时若展示同账号旧缓存，必须标明来源与未重新验证状态。
6. 若模板里存有当前字典无法验证的非空ID，保留显示并提示“原选项当前不可用”，在真实options之外显示该历史值并提供显式清除；阻止带该失效条件提交，直到重新验证或用户显式清除。不能把历史ID注入options伪造成可选项，也不能自动清空后查询扩大范围。
7. 文件管理/期限监控的ID字段不退化为自由文本；递交管理保留签约单位的既有显式手填例外，不影响真正的文本条件。

## 验收

三个查询表分别覆盖加载中、成功空、失败重试、成功有树、搜索无匹配及旧模板值。ApplyTags=null时点击字段不得出现空菜单或全选；刷新拿到真实数据后可正常选择和提交ID。原有已选择ID不会被隐式丢弃，案件状态按案件类型过滤保持不变。

已实施并通过字典、缓存、控件和三个查询表专项回归；真实构建浏览器夹具确认 ApplyTags=null 时呈现静态提示。
