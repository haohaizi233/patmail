# 文件管理恢复账本与下载续传设计（待确认）

## 意图与现有证据

用户要求文件管理的WAL保护覆盖查询和下载，中断后能够继续，保留已认可的6令牌解析/传输流水与低内存特性。

- `FileSearchQuery.vue` 的查询结果、分页、勾选、下载标识为组件内存状态；`FileSearchPanel.vue` 重新检测会话会清选择并触发视图清理。
- 现有 `file-desk` 恢复槽由 `FileManageMail.vue` 用于发文工作面，不包含上述文件查询工作面。`file-search-snapshot.ts` 是有时效和重新验证要求的查询证据，也不是完整UI/下载检查点，且其观察文件模型不含下载所需的fileNo。
- `nativeStreamArchive` 的finally无条件abort；后台Job只存在Map里；Python桥接把字节从deque取出即丢弃，GET只能claim一次，没有Range。断开还会清空队列。Chrome的“继续”无法找回这条生产链。
- `indexedRecoveryStore` 的写入在IDB request.onsuccess时返回，未等待事务提交；每个页面实例以各自SQLite内存库的maxSeq分配序号。已用双实例及IndexedDB式序号键存储复现：不同scope的两次写入均分配seq=1，持久帧只剩最后一笔，应保留2笔的断言失败。临时证据在忽略入库的`test-results/wal-multiwriter-repro.log`。多实例冲突已确认；旧检查点覆盖也需纳入修复验收。
- `FilesPage.vue` 按authenticated状态v-if切换整个查询面；切换会卸载查询组件。卸载清掉内存结果和选择，但全局命名进度未按任务关联恢复/收尾，对应截图的“空结果+54.8%”。

## 方案比较与建议

1. 失败后从头重试：改动少，但已下载内容丢失，不符合续传要求。
2. **建议：持久化任务 + 有界磁盘字节缓存 + 本机Range服务。** 继续保留解析、取文件和生成ZIP的流水，增加磁盘恢复边界。
3. 全部下载完才生成最终包：恢复较简单，但推迟首个下载字节，破坏用户已认可的流水体验。

## 工作面和WAL

- 新增文件查询专用恢复槽，与发文工作面分开。用完整的origin、operatorId和页面用途构造无截断身份键；不沿用会截断到200字符的旧scope拼接。旧记录缺owner时隔离待确认，不自动归入当前账号。
- 保存查询条件/模板和临时编辑、当前页与已读页索引、完整选中文件（含fileId、fileNo、原名、顺序）、下载名称配方与去点设置、关联任务ID和显示状态。大页数据增量保存，不每次进度变化重写整个1607行数组。
- 查询结果返回、勾选变更、下载开始、命名批次完成、文件缓存完成、ZIP写入确认分别记账；下载开始前必须收到持久化提交确认。普通输入可合并写回，关键检查点不能只等pagehide。
- 恢复先呈现本地工作面和暂停任务，不自动清空并重查。查询证据与可继续执行的权限独立：恢复的查询证据仍需重新验证；发文不会因为UI恢复而自动执行。
- 以扩展后台作为生产WAL的单写入权威，迁移所有现有生产调用方，页面保留现有调用接口，通过已校验的扩展消息提交和读取；后台冷启动先重放持久化帧再接受读写RPC或分配序号。写入以事务oncomplete为成功，onabort/onerror都返回失败。检查点提交与对应帧清理置于原子IDB事务，读写统一排序。
- 同scope工作面携带expectedRevision；旧页面提交与当前版本冲突时不得覆盖较新的工作面，返回冲突并要求读取新版本/显式合并。下载任务由当前租约所有者推进检查点，避免多个页面都继续同一任务。
- 页面卸载、掉登录或账号切换先暂停并保留工作面。进度条从恢复任务状态派生，不保留一个没有关联任务的“运行中54.8%”。存储失败明确显示未保护状态，不能吞错后宣称已保存。

## 下载任务和两段续传

任务清单冻结文件顺序、查询来源、名称配方、生成名称及其批次、ZIP时间戳和构造参数、协议版本、文件/字节检查点、浏览器downloadId和阶段。修改名称另建任务，不能混写旧任务。

### 原站到本机

- 在保留6个共享令牌和每份256KiB应用队列的前提下，将正文逐块写入专用磁盘缓存；已确认完成的附件不再向原站读取。
- 网络中断可恢复，不直接当作用户丢弃任务。当前附件保存已确认长度与可用的ETag/Last-Modified等版本证据。
- 若原站支持Range，校验206、Content-Range、起始偏移和版本后续取；若返回200、版本变化或不支持Range，只重取这份未完成附件，禁止把完整响应追加到已有片段。登录失效暂停，重新确认同一账号后继续。
- 下载名称按批次持久化，已生成名称不全部重跑。后台重启、EASY刷新后通过持久任务重新绑定来源页，不能依赖旧tab/frame内存状态。

### 本机到浏览器

- 桥接由纯内存中转升级为有界内存、顺序磁盘spool。PUT包含任务、顺序/偏移和块摘要，落盘与元数据提交后才确认；重复提交同块返回已确认结果，冲突拒绝，不静默重复追加。
- 初次GET保持200 chunked流水。发生浏览器中断后，插件先恢复生产并封存完整本机ZIP，再发起浏览器resume；以已知最终长度提供正确的206/Content-Range、Content-Length和稳定ETag。尚在增长的spool不能用虚构末字节或无限206响应；界面区分“恢复文件/生成压缩包”和“续传到浏览器”。提前点击Chrome继续时，用可重试未就绪状态并由插件在封存后主动恢复，不能长期悬挂请求。
- 实施的首个协议验证里，必须用真实Chrome确认初始chunked下载在中断后canResume为true，且同一downloadId向稳定URL发出非零起点Range后能完成。不能把调用resume API或生成了另一个ZIP当作通过。若下载历史已删除或Chrome明确不支持该记录续传，只能明确提供“从本机缓存另存为新文件”，不能宣传为原浏览器记录的字节续传。
- 浏览器接收中断时保留任务、ZIP spool和附件缓存，暂停/重连；将“暂停、继续、取消并保留、丢弃并清理”区分，不再在finally里统一删除。
- 生产进程重启时从已确认附件缓存重建ZIP输出。固定时间戳、条目顺序、命名、zip.js/协议版本和ZIP64/STORE配置；缓存回放也包装为与原生产一致的未知长度ReadableStream，不能换成已知大小Reader改变本地头/数据描述符字节。对既有spool逐块验证相同前缀，只有字节一致才续追加并允许旧浏览器偏移继续。若不一致，停止旧表示并明确创建新下载，禁止拼出损坏ZIP。
- 校验成功的完整文件不重新走原站网络；重建可能重读本机缓存。现有zip.js的内存对象不作为可持久化ZIP写入状态，不依赖其私有字段。
- 最终成功需ZIP关闭/校验与浏览器complete均确认。用户取消的残包不标成功；源数据失效时显示不可恢复的具体原因。

### 持久水位协议

桥接的字节落盘水位为权威：先写块并flush/fsync，再原子替换并提交块摘要/偏移清单，最后ACK。Windows上的关闭句柄、fsync、原子替换与失败恢复必须单独验证。扩展WAL允许落后于桥接，但不能提前标记已确认；重启依据桥接已提交清单核对摘要，截去未提交尾部，再补齐扩展WAL。不能仅凭文件长度宣称某一块已提交。

## 磁盘和身份边界

- 必须使用本机临时磁盘；建议缓存放本机应用数据的PatMail专用目录。附件缓存与ZIP spool并存时，磁盘需求可能接近源文件和ZIP两份，不转为整包内存。
- 建议成功确认后自动清理；中断任务默认保留7天，自最近一次暂停/失败或用户显式继续的时间计时，不被状态轮询和心跳延长。启动和定期扫除均排除活动任务；清理与恢复持有互斥租约。空间不足时暂停并保留已确认部分，提示可恢复的状态，不自动删除其它任务。
- 不保存Cookie或密码。任务、恢复和续传授权绑定origin/operator，未重新验证身份不重新访问原站；换账号撤销活动写入/续传授权并关闭现有GET连接。下载URL表示稳定任务，写入/恢复授权令牌可轮换，两者分开；GET没有Origin可依赖，桥接必须依据任务授权状态决定是否供数，仅同一owner重新验证后才启用。
- 桥接只使用服务端生成的缓存路径和能力令牌，不接收任意文件系统路径。故障日志不输出业务正文、登录凭据或可复用能力令牌。

## 验收

- 1607文件规模查询/勾选/命名中途刷新，视图和选择装回；进度显示暂停或真实任务阶段，不出现空查询结果配运行中进度。
- 双页面交错WAL写入、事务在request成功后abort、检查点前后退出、后台重启，均不丢帧、不串scope、不重复执行发文。
- 名称生成到880/1607断开，恢复后只生成缺失批次；已缓存完整附件不再次从原站取。
- 模拟原站断网/206续取/忽略Range返回200/ETag改变/登录过期，检查偏移、请求次数和最终内容。
- 浏览器在已收若干MiB后断开并点击继续，确认后续Range起点非0、磁盘前缀一致、同一表示的下载能完成。
- 桥接退出重启、工作台刷新、EASY刷新、扩展后台冷启动均恢复任务；源身份不匹配时不继续。
- 保持6路并发和有界内存；最终ZIP逐条文件名、顺序、长度、内容和独立CRC核验。覆测空间不足、7天清理及显式丢弃。
