# 文件管理恢复与断点续传（v1.5.0）

## 使用

运行仓库 `start.py`，或 `dist/local-download/start-stream-download.ps1`，然后在扩展管理页重新加载 `dist`，刷新 EASY 来源页和工作台。桥接健康检查必须返回 `version: 2`；启动器遇到旧桥接会明确提示关闭旧进程后重启。

查询条件、当前结果、分页记录、跨页勾选、命名配方、申请号去点设置和下载任务按「EASY 站点、用户、工作面」保存。刷新或重新打开页面后先恢复只读工作面，点击“刷新”重新确认查询，再继续下载。恢复不会自动查询或发文。其他账号的工作不会混入当前账号。

下载中离开页面或连接失效会暂停任务并保留缓存；回到同一账号后点击“继续下载”。任务使用开始时冻结的文件清单和命名配方。要改配方重新开始，先明确“丢弃下载任务”。丢弃会删除该任务的本地续传缓存。

首次下载仍是未知总长度的流，解析、取文件和写 ZIP 并行运行，共用六个动态令牌。彩虹条只显示名称解析；传输字节和终态由浏览器下载记录显示。

## 持久化与续传

后台是恢复账本唯一生产写入方。读取、冷启动回放和写入排队，IndexedDB 事务完成后才确认保护；同一工作面的旧版本写入会拒绝，避免多窗口覆盖新状态。

本机桥接只监听 `127.0.0.1:42843`。缓存默认放在 `%LOCALAPPDATA%/PatMail/download-cache`，使用独占锁防止多个桥接同时写入。它保存附件片段、生成的 ZIP 片段、命名批次和必要任务元数据，不保存 EASY Cookie 或密码。字节先落盘，再原子提交元数据；重启时丢弃未提交尾部并校验已提交片段。磁盘空间不足、损坏、账号不符或重放前缀不一致会明确失败，不把残缺包报告为完成。

恢复时完整附件直接从缓存读取；部分附件在有可靠版本标识时以 `Range`/`If-Range` 补传。服务器不接受 Range 或内容版本改变时，仅重取该未完成附件。冻结 ZIP 时间、条目顺序和名称后，可确定性重放并核对已确认 ZIP 前缀。

ZIP 封存前总长度未知；封存后才响应最终长度的 HTTP 206。插件优先恢复同一条 Chrome 下载记录，从该记录已接收位置继续。Chrome 不允许原记录续传、记录已清除时，会提示显式“从缓存另存为新文件”；不会默默建立第二条记录。

浏览器报告完成后，桥接先保存完成回执，再删除大块附件和 ZIP 缓存。即使页面恰好没收到完成回执，恢复时也能识别已经完成，避免重新下载。暂停任务和小型完成回执保留七天；心跳不会无限延长暂停任务寿命。清除扩展数据、手动删缓存或超过保留期会失去对应恢复能力。

升级前中断的旧下载没有这套缓存，不能补出历史断点，需要重新下载一次。

## 空下拉

三个查询表区分“读取中”“读取失败，可重试”和“确认没有选项”。`ApplyTags: null` 显示“当前账号未配置专利标签”，不再显示可展开的空下拉、搜索或全选。明确空数据覆盖旧缓存和静态兜底；接口失败不会冒充空数据。历史已选但失效的 ID 会提示清除，并在处理前阻止提交。递交管理的签约单位保留明确的手填例外。

## 回归入口

`npm test`、`npm run test:stream-bridge`、`npm run build` 验证账本、生产者、协议和构建。`npm run test:e2e:durable-download` 用真实扩展和本机桥接验证源文件补传、同一原生下载 ID 的非零 Range 及 ZIP CRC；`npm run test:e2e:download-editor` 验证查询一次后换名称重复下载、空标签静态提示和整页恢复；`npm run test:e2e:stream-download` 验证 81 文件、六条连接、取消和顶层导航。

浏览器业务响应使用隔离夹具，续传测试数据不代表真实 EASY 服务一定支持附件 Range；不支持时会按上述规则重取未完成文件。
