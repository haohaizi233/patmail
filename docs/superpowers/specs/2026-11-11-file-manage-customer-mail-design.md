# 文件管理工作流：客户专属发文配置

## 需求与范围

在添加、修改客户时配置文件管理发文的七项设置，持久保存并由真实执行链路使用。配置属于客户工作流记录（CustomerQueryProfile.id），同客户的不同工作流记录可独立设置。未设置的字段沿用现有逻辑，不修改全局发文映射。此次不扩展 PCT 工作流。

## 方案

采用客户记录上的可选发文配置，执行时逐项解析“客户覆盖 → 原有默认”。现有客户记录、版本校验、存储及恢复机制继续使用。

不采用按客户复制整套全局规则：复制后默认配置变化无法自然继承；不采用仅在任务页临时选择：无法满足创建客户时保存、后续自动生效的要求。

## 字段与实际行为

| 字段 | 客户可选配置 | 留空时行为 |
| --- | --- | --- |
| 发文类型 | 热加载发文类型树，选择该客户固定使用的类型 | 按文件描述一对一匹配全局映射 |
| 收件人 | 追加多个姓名、邮箱；保留案件联系人；按邮箱去重 | 仅案件联系人 |
| 抄送 | 建议允许开关“发件人”“商务”，并追加多个姓名、邮箱 | 当前发件人和商务 |
| 发件人 | 热加载原站发件邮箱下拉，保存选中的编号及展示信息 | 发文映射默认发件人 |
| 审核人 | 热加载原站审核人下拉 | 发文映射默认审核人 |
| 标题 | 客户独立标题模板，使用现有模板变量和校验规则 | 发文映射标题模板 |
| 签名 | 热加载原站邮件签名下拉，选项保留来源与编号 | 发文映射默认签名及现有原站默认逻辑 |

用户已确认抄送开关，并补充每项启用后可热加载下拉 DIY，末尾允许继续追加。空配置与显式关闭应区别保存；删除覆盖即恢复默认。收件人追加不替换案件联系人。

## 界面与数据

客户添加、编辑表单在选择“文件管理”时显示专属发文设置，字段标明“留空使用默认”，下拉支持重新读取。编辑旧客户不自动写入当前全局默认，以免把继承变成固定覆盖。切换客户、取消、重开表单不得残留其他客户的值。

客户保存、读取校验、导入导出、复制及恢复需保留新字段并正确复制嵌套配置；使用现有版本冲突检测。使用原站选项编号，执行时重新读取所需数据，不持久复制原站签名 HTML 为过期快照。

## 执行链路

FileManageMail 规划前解析该客户的发文类型、标题、发件人、审核人和签名覆盖。覆盖发文类型时不再因全局缺映射阻塞该封；其他文件、客户隔离、标题校验仍保留。

提交项携带解析后的选择和收件人、抄送规则，消息类型与运行时校验同步扩展。创建仍使用已确认的 mailstyle=1/2。执行器创建后读取案件与商务联系人，追加收件人、组装抄送，保存到 SaveMailInfo，并按所选审核人提交。抄送中的“发件人”指本封最终采用的发件人。

显式选择的原站项目失效时报告具体原因，不静默改发给默认人员；只有未配置的字段才回退。联系人读取失败与写入结果未知保留现有停止、账本与防重复机制。

## 验证与交付

测试无覆盖时行为不变、每字段覆盖及回退、两客户隔离、保存后重新加载生效、收件人追加去重、抄送关闭与追加、原站选项失效、消息校验、创建/保存/审核请求实际携带客户设置。运行相关回归、类型检查和构建，更新客户管理与文件管理说明。真实业务写入不用于自动测试。
