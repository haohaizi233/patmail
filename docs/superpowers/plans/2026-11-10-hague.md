# 海牙批量新申请 Implementation Plan

**Goal:** 从用户选择的总目录识别多件海牙申请，解析材料、读取知易通、统一 Agent 仲裁并供核对使用。
**Architecture:** Vue 工作流工具入口；本地 DOCX XML 解析与逐案隔离；沿用已绑定 EASY 通道及 Agent 配置。
**Tech Stack:** TypeScript、Vue、zip.js、Vitest。

## Constraints
- 递归目录，最近的案件目录拥有文件；不跨案件配图。
- 按 No/Code/Legend 三列为一组解析，Code 00 才使用自定义 Legend。不能用表格位置推断视图。
- 申请人和设计人地址保留到区，设计人复用申请人地址，城市省份独立。
- 文件夹/文件名案号冲突需用户纠正；单案错误不影响其余案件。
- 本轮先实现材料准备及仲裁工作台；站点自动写入须在真实弹窗选择器得到验证后接入，不能用猜测控件自动保存。

## Tasks
- [x] 目录识别、DOCX 解析及编号校验：先添加嵌套/错配/Code 00/缺图回归，再实现。
- [x] EASY 专用只读信息加载及 Agent 仲裁，保留原文与缺失提示，验证返回结构。
- [x] 工作流入口、批量逐案处理、预览及导出；运行定向测试、类型检查与构建。

## Review Focus
同名文件隔离；Word 案号冲突；数字自然排序；重复和缺失图片；Agent 无效或不完整结果。
